## 残影与截断修复（2026-10-25 夜，1.1.4）

虎哥反馈：舔爪播放中能看到「残影」，且动作像没演完就断了。逐项定位到三个独立缺陷，**素材本身干净**（半透明边缘 908–938 px，比 idle 的 1553–1599 更少，不存在抠图残影）。

| # | 缺陷 | 机理 | 现象 |
|---|---|---|---|
| 1 | 用墙钟计时，动画却按 `dt × animSpeed()` 推进 | 默认动效 85%，2 轮实际 1.9/0.85 ≈ 2.24 s，而 `pet.lickTimer` 1.9 s 就收摊 | 收爪帧 `lick_4` 永远播不到，动作在 85% 处被掐断 |
| 2 | 帧间插值窗口用 `1/fps`，没算 `hold` 覆盖 | 主帧停留 350 ms，`t` 在 130 ms 就进窗口、200 ms 时 `k=1`（下一帧满不透明盖上），205–342 ms 又反向淡出，`t>1.71` 后 `inOutQuad` 变负 | 「下一帧闪一下又消失」的残影 |
| 3 | 插值实现是「当前帧实心 + 下一帧按 k 叠加」 | `lick` 相邻帧 IoU 仅 0.86–0.95，两轮廓同时可见 | 双爪 / 双头双影 |

**修法**：

- `animator.frameDur(name, idx)` 统一给出实际停留时长；`_drawSeq` 用它算窗口，`t`、`k` 均夹取到 `[0,1]`。
- 新增 `NO_FRAME_BLEND = new Set(['lick'])`，舔爪改**硬切**；其他姿态保持原插值（有对照断言防误伤）。
- `pet.lickEnd = animator.clock + rounds × LICK_CYCLE - LICK_END_TRIM`，挂动画时钟；`LICK_END_TRIM = 0.1`（半帧）避开环回闪回抬爪。
- 状态淡入 `0.18 → 0.12`，缩短 idle↔lick 双姿态可见时间。

**回归断言（新增 8 条）**：不参与插值 / 窗口按时长计算并夹取 / 结束挂动画时钟 / 弃用墙钟 / 完整播满 2 轮（`12341234`）/ 末帧必须是 `lick_4` / 收尾提前半帧 / 主帧 350 ms 全程每次绘制仅 1 张（`1/1/1/1/1/1/1`）+ 对照 idle 仍插值 2 张。

## 走/跑「最少 2 循环」改造（2026-10-25 深夜，1.1.5）

**需求**：走/跑播放不得过短，至少完整 2 个循环；循环衔接自然、首尾对齐；不跳帧不停顿。

**先量素材**（`tools/sprites/loop_seam_audit.py`）：接缝并不比普通相邻帧更陡，问题出在「播放被随机距离截断」。

| 姿态 | 普通相邻帧 IoU | 接缝 `末→首` IoU | 判定 |
|---|---|---|---|
| `walk` | 0.593–0.750 | **0.624** | 与普通帧同量级 OK |
| `run` | 0.558–0.632 | **0.680** | 同期最平滑 OK |
| `idle` | 0.969–1.000 | 0.966 | OK |

**改造**：

1. `animator.laps` 轮数计数（环回首帧 +1，动画时间域）+ `lapsDone()` / `atCycleStart()` / `cycleSec()`。
2. `WALK_MIN_LOOPS = RUN_MIN_LOOPS = 2`；状态只在 `laps ≥ 2 且 frameIndex === 0` 时切换 → 切换点必在循环接缝，不停在半截跨步。
3. 步速反算：`walkSpeed = min(WALK_SPEED, 距离 / 0.727s)`，`runSpeed = clamp(距离/0.615s, 0.65×RUN_SPEED, RUN_SPEED)`；单帧位移不超过剩余距离 → 到达时刻≈满 2 轮，不冲过头、不抖动。
4. `pickTarget(minDist)`：自由漫游只选距离 ≥ `WALK_MIN_DIST(70)` / `RUN_MIN_DIST(145)` 的一侧；两侧都不够（屏幕窄）去更宽敞那头。
5. `run` 到点若不足 2 轮 → 换远目标继续冲，不走走停停。
6. `WALK_SKIP_DIST = 24`：碗/光标贴脸（< 24 px）不播步态，直接进后续动作。
7. `NO_FRAME_BLEND` 扩到 `{lick, walk, run}`：走/跑 IoU 仅 0.56–0.75，帧间插值会叠成「四条腿」。

**回归**：新增 12 条断言（帧率/轮数/门禁/边界收尾/插值排除/步速反算/跑速下限/贴脸跳过/animator 轮数单测 + 40 s 自由漫游逐段校验「≥2 轮、收在首帧、帧序不跳」）。全量 **100% 通过**，连跑 3 次稳定。另把「摇尾巴」抽样窗口 150→230 s（走/跑变长后决策次数变少，原窗口偶发漏抽翻红）。

**真机**（打包版，`tools/probe/probe_locomotion.js` 钩 `Animator.prototype.draw`）：120 s 采样 → walk 9 段（4 段满 2 轮 / 5 段贴脸跳过）、run 4 段全部满 2 轮，帧序无跳变、无卡死段。

## 摇尾巴残影/体型 + 状态分布调整（2026-10-26，1.1.6）

**需求**：① 摇尾巴有与舔爪相同的两个毛病——残影 + 短暂体型变化，要求全程无残影、体型稳定；② Idle 成为主要动作，走/跑降频，各状态过渡自然。

### ① 残影：量化后加进硬切集合

实测 alpha 掩膜 IoU（`tailwag_1→2` 0.781、`2→3` 0.916、`3→4` 0.761、`4→1` 0.764），与 `lick`(0.86–0.95)、`walk`(0.59–0.75) 同一档，远低于 `idle`(0.966–1.000)。帧间插值是「当前帧实心 + 下一帧按 k 叠上去」，两条处于不同角度的尾巴会同时可见 → `NO_FRAME_BLEND` 加入 `tailwag`，改硬切（7 fps 的 4 帧关键帧，硬切即标准精灵节奏）。

顺带把退出时机改到循环接缝：`pet.tailwagEnd = animator.clock + rand(2.2,3.6)`（动画时钟，动效 85% 不缩水），退出条件是 `clock ≥ end && atCycleStart()` —— 不然硬切会在「尾巴甩到一半」定格再淡出。

### ② 体型：放弃运行时系数，比例烘焙进素材

根因不是逐帧尺度抖动，而是 `POSE_SCALE.tailwag = 0.85` 这个**离散查表 + 帧级平滑**的组合：切进该姿态时系数整块生效，被 `SCALE_SMOOTH` 在 0.35 s 内渐进应用 → 观感就是「短暂缩一圈再涨回来」。

量尺子的过程本身踩了两个坑：

| 口径 | 读数 | 结论 |
|---|---|---|
| 整幅 alpha 核心面积 | idle 71280–72798 / tailwag 89900–106681（+26%） | ❌ 被尾巴污染（甩到侧后、绕头） |
| 躯干带 `x∈[160,352]` 腐蚀核心 | tailwag 61947–68108（组内 4.6%） | ❌ 带内仍会横进尾巴，且行宽早已饱和 |
| **眼距（两眼中点距）** | idle_1 **95.9** / tailwag_1..4 **103.1–103.6**（组内 0.6%） | ✅ 刚性特征，不受尾巴与姿态影响 |

眼距结论：摇尾巴素材整体比 idle 大 **7.5%**（`0.85` 属于过度收缩，脸反而比 idle 小 8.6%，同时也解释了"缩一圈"的另一种成因）。逐帧系数 0.9258 / 0.9309 / 0.9310 / 0.9294，锚点 (256,470) 保脚底贴地，原始帧备份 `_backup/pose-orig/`。归一后复测眼距 96.1–97.1（与基准差 0.8%）。

改造后 `POSE_SCALE = { pet: 1.08, unhappy: 0.84, bath: 0.87 }`，`tailwag` 运行期系数恒为 1，进出该状态**没有任何尺寸过渡**。工具：`tools/sprites/normalize_pose_size.py <pose> --ref idle_1 [--metric eye|torso] [--dry]`。

> 遗留：`pet / unhappy / bath` 仍在 `POSE_SCALE` 里（闭眼/侧脸帧测不到眼距）。按眼距可测帧估算，理论系数应为 `pet≈1.05`、`unhappy≈0.90`、`bath≈0.94`，比现值均偏保守 4–6%。若要彻底消除这三处的过渡，可用同一支工具烘焙。

### ③ 状态分布：idle 转正

| 活跃度 | idle | walk | run | 走+跑 |
|---|---|---|---|---|
| `low` | 0.39 → **0.55** | 0.28 → 0.22 | 0.07 → 0.05 | 0.35 → 0.27 |
| `normal` | 0.16 → **0.42** | 0.36 → 0.24 | 0.16 → 0.11 | 0.52 → 0.35 |
| `high` | 0.05 → **0.30** | 0.34 → 0.26 | 0.24 → 0.16 | 0.58 → 0.42 |

三档权重和仍恒为 1.00（`meow` 在决策链末位吃掉余量）。过渡依旧走统一淡入（`play(..., 0.12–0.22)`）+ 循环接缝收尾，未新增任何硬切。

**回归**：新增 11 条断言（`NO_FRAME_BLEND` 含 tailwag / `POSE_SCALE` 不含 tailwag / 计时挂动画时钟 / 双条件退出 / 143 ms 内只绘 1 张 / 50 s 回放每段收在首帧且 ≥2 轮 / 三档 idle 均为第一权重 / 权重和为 1 / normal 走跑降幅）。全量 **437 项通过**。

## 抚摸尺寸修正 + 切回 idle 无跳变（2026-10-26，1.1.7）

**需求**：抚摸动作尺寸不正确；切回 idle 时尺寸突变，要求过渡平滑无跳变。

**根因**（两个叠在一起）：

1. 素材本身偏小。`pet_1..3` 的整幅 alpha 面积只有 idle 组均值的 **78–81%**（62574/61168/63225 vs 77789），头宽 235–245 vs 288 —— 抚摸期间猫明显小一圈。
2. 运行期拿 `POSE_SCALE.pet = 1.08` 去补，既补不够，又因为「离散查表 + 帧级平滑（`SCALE_SMOOTH`，≈0.35 s）」变成一次可见的缩放动画：进抚摸 → 涨 8%，切回 idle → 缩 8%，观感就是"大小不对 + 切回突变"。

**判据选择**：抚摸帧基本闭眼（3 帧只有 `pet_1` 测得到眼距 91.1），`--metric eye` 不可用；改用**整幅 alpha 面积**（人眼判断"整体多大"的量），并加 `--uniform` 取组内统一系数，避免逐帧缩放带来帧间抖动。

| 口径 | idle 基准 | pet | 系数 |
|---|---|---|---|
| 整幅面积 | 77789（4 帧均值） | 62574 / 61168 / 63225 | 1.1150 / 1.1277 / 1.1092 → **统一 1.1173** |

**改造**：

1. `python tools/sprites/normalize_pose_size.py pet --ref idle --metric area --uniform`：三帧统一放大 1.1173（锚点 256,470），原始帧备份 `_backup/pose-orig/`。归一后组均值与 idle 差 **+0.1%**，单帧 −1.8%~+1.5%。
2. `POSE_SCALE` 删除 `pet` → `{ unhappy: 0.84, bath: 0.87 }`。运行期系数恒为 1，抚摸 ↔ idle 之间**不存在任何尺寸过渡**（不是"更平滑"，而是根本没有缩放量）。
3. 工具升级：`--metric area`（整幅面积，`--uniform` 配套）、`--ref idle`（无编号时取该姿态全帧均值，抹掉基准自身的帧间波动）。

**回归**：新增 4s 段 4 条断言（`POSE_SCALE` 不含 pet / 抚摸段体形系数恒为 1 / 切回 idle 衔接处差 0 / idle 段恒为 1）；`verify_asar` 增 2 条；新增真机 `tools/probe/probe_pet.js`（4 次抚摸，校验段内系数恒 1、切回衔接差 0、帧序推进）。全量 **440 项通过**，连跑 4 次稳定。

**顺带修测试稳定性**：1.1.6 把 idle 权重调高后，4p（走/跑）与 4q（摇尾巴）的随机抽样次数变少，出现偶发翻红——其中"31 帧/1 轮"的异常段其实是**紧急需求打断**（`walk` 在 `INTERRUPTIBLE` 里），不是缺陷。现改为：只对"正常退出（下一步回 idle）"的段做「≥2 轮 + 收在循环首帧」强断言；摇尾巴随机未命中降级为 `[warn]`（触发覆盖由 phase4 的 230 s 窗口兜底），采样窗口 2400→3600 帧、3000→6000 帧，`activityLevel` 提到 `high`。

## 伤心尺寸修正 + 切回 idle 无跳变（2026-10-26，1.1.8）

同一类缺陷的第三次复现（前两次是 tailwag 1.1.6、pet 1.1.7）。

**根因**：

1. `unhappy_1/2` 两帧素材比 idle **大 17.5%**（底边锁高 398 / 397 px vs 338），运行期靠 `POSE_SCALE.unhappy = 0.84` 压回去。
2. `draw()` 把**同一份 `mods` 同时传给 `prev` 和 `current`**：淡化期（0.16–0.22 s）里退场的伤心帧用的是**已切到 idle 的** `poseCur`，于是伤心帧在仍然 100% 可见时先被放大 19%，再淡出。这条比"系数本身"更伤——观感是持续的大小脉动。
3. 反方向同理：进伤心时，伤心帧一边淡入一边缩到 0.84。

**判据选择（三套口径互相矛盾，必须逐个排除）**：

| 口径 | unhappy_1 / 2 | 系数 | 结论 |
|---|---|---|---|
| 底边锁高 `--metric height` | 398 / 397 | 0.8492 / 0.8514 → **统一 0.8503** | ✅ 两帧都测得到，跨帧差 0.25% |
| 腐蚀核心（331 基线同源） | 1.462 / 1.326（相对 idle） | 0.827 / 0.868 → 0.848 | ✅ 与上一行收敛 |
| 眼距 `--metric eye` | 107.3 / —（第 2 帧闭眼） | 0.8961 | ⚠️ 只覆盖 1 帧 |
| 躯干带核心 `--metric torso` | 8773 / 7845 | 1.0111 / 1.0692 | ❌ **饱和**：体宽 321 px 远超 132 px 测量带 |
| 整幅面积 `--metric area` | 112319 / 102237 | 0.8322 / 0.8723 | ❌ 被绕到身前的尾巴污染 |

判据定型为**底边锁高**：站在地面上的角色，「可视高度」最接近人眼判断"这只猫有多大"；耷拉耳和绕身尾巴只改宽度不改高度，既不污染也不会饱和，且两帧高度本身只差 0.25%（跨帧不受帧间抖动影响）。

**改造**：

1. 工具升级：新增 `--metric height`（底边锚定 bbox 高度，线性量）。
2. `python tools/sprites/normalize_pose_size.py unhappy --ref idle --metric height --uniform`：两帧统一 ×0.8503（锚点 256,470），原始帧备份 `_backup/pose-orig/`。归一后高度与 idle 差 **−0.1%**；交叉核对眼距 0.978、头宽 1.054、胸宽 1.024、骶宽 1.009、腐蚀核心 1.045 / 0.947。
3. `POSE_SCALE` 删除 `unhappy` → `{ bath: 0.87 }`。运行期系数恒为 1，伤心 ↔ idle 之间**不存在任何缩放量**。

**回归**：新增 4t 段 4 条断言（`POSE_SCALE` 不含 unhappy / 伤心段系数恒为 1 / 切回 idle 衔接差 0 / 全时段无帧间变化，含淡化期）；`verify_asar` 增 1 条；新增真机 `tools/probe/probe_unhappy.js`。全量 **444 项**，连跑 3 次稳定。

**真机实测**（1.1.8 打包产物，config 里预置 `happiness=5` 让 P4 持续触发）：采样 18745 帧、**23 段伤心**、3817 帧，段内系数最大偏差 **0.0e+0**，15 次切回 idle 衔接差 **0**，全时段系数无帧间变化。每次时长 1.25–4.02 s（低于 2.6 s 的是被 meow/紧急需求打断，`unhappy` 在 `INTERRUPTIBLE` 里，属设计允许）。画布快照对照：idle **132×149** vs unhappy **132×148**（差 1 px），见 `design/checks/unhappy-size-1.1.8.png`。

**遗留**：`bath` 是最后一个还在 `POSE_SCALE` 里的姿态（`0.87`）。6 帧、泡沫与水面污染所有面积类口径，需要逐帧人工定锚才能烘焙；只要它还在，上面第 2 条根因（`prev` 共用 `mods`）就仍然存在。
