# 小猫桌面宠物 · 设置功能方案（评审稿）

> 版本：v1（2026-10-15） · 状态：**待确认** · 确认后进入实现
> 关联文档：`design-plan.md`（总体方案）、`cat-pet/README.md`（已实现功能）

---

## 一、目标与范围

为桌面宠物补齐"通用桌面应用级"的配置能力，让用户能按自己的习惯调整宠物的身份、外观、行为与数据存放方式。

本轮交付范围锁定为**三件事**：

1. 一套**完整的设置项清单**（名称 / 作用 / 取值 / 默认值 / 生效时机）；
2. 一个**独立的设置窗口**（不干扰宠物窗口的透明置顶特性）；
3. 一套**统一的配置持久化与分发机制**（主进程唯一真源 + IPC 广播联动）。

**明确不做**（避免范围蔓延，如需要可单独立项）：账号登录/云同步、多宠物管理、皮肤包下载、插件系统。

## 二、设置项的呈现形式

### 2.1 文档呈现形式（本方案）

采用**分组表格**。每张表 8 列，字段含义如下：

| 列名 | 含义 |
|------|------|
| 设置项 | 界面上显示的中文名称 |
| 键名 | `config.json` 中的字段名（英文，驼峰） |
| 作用 | 用户视角能感知到的效果 |
| 取值 / 范围 | 类型与合法区间（含步长、枚举值） |
| 默认值 | 首次运行的初始值 |
| 生效时机 | 即时 / 重启 / 下次登录 |
| 优先级 | P0 = 必做；P1 = 建议做（可裁剪） |

### 2.2 应用内呈现形式（设置窗口）

**结论：采用独立设置窗口，而非"猫身旁浮动面板"。**

理由：设置项近 30 条，浮动面板空间不足且与宠物交互区重叠，容易误触；独立窗口可复用系统标题栏、支持键盘 Tab 导航与滚动，符合"通用桌面应用"的习惯预期。

窗口规格：

| 项 | 值 |
|----|-----|
| 尺寸 | 620 × 580（固定，不可缩放） |
| 样式 | 标准系统标题栏（`frame: true`），可最小化，**不置顶、不进任务栏**（跟随托盘应用惯例） |
| 层级 | `parent` 指向宠物窗口，非模态（模式化会挡住宠物） |
| 单例 | 全局仅一个；重复打开时 `show()` + `focus()` 聚焦已有窗口，不新建 |
| 打开入口 | 托盘菜单「设置…」、宠物右键菜单「设置…」、双击托盘（已占用则改为菜单项） |

布局：左侧分组导航（140px）+ 右侧表单内容区 + 底部操作条。

```
┌──────────────────────────────────────────────────────────┐
│  设置 - 小猫桌面宠物                              _ □ ×  │
├─────────────┬────────────────────────────────────────────┤
│ ▸ 宠物      │  宠物                                      │
│   启动与运行│  ┌──────────────────────────────────────┐  │
│   交互      │  │ 宠物名字   [ 小银            ]       │  │
│   声音与通知│  │ 主人称呼   [ 主人            ]       │  │
│   外观与主题│  │ 体型大小   ├──●──────┤  62%         │  │
│   行为活动  │  │ 显示阴影   [ ● ]     粒子特效 [ ● ]  │  │
│   数据与存储│  └──────────────────────────────────────┘  │
│             │                                            │
│             │  ⟳ 标有「重启后生效」的项在下方显示徽标     │
├─────────────┴────────────────────────────────────────────┤
│  恢复默认设置                    [ 取消 ]  [ 应用 ]       │
└──────────────────────────────────────────────────────────┘
```

交互约定：

- **改动即预览**：能即时生效的项（体型、透明度、主题、语言）在表单上改动后立刻反映到宠物窗口，无需点「应用」；
- **底部按钮语义**：「应用」= 强制落盘 + 收起重启徽标提示；「取消」= 回滚到打开窗口时的快照（仅对未落盘项）；
- **重启生效项**：在该项右侧显示橙色徽标 `重启后生效`，并在底部操作条出现「立即重启应用」按钮；
- **校验反馈**：输入非法（超长、含控制字符）时输入框红边 + 下方红字说明，且不写入配置。

## 四、数据模型与持久化

### 4.1 唯一真源

**主进程内存中的 `config` 对象是唯一真源**。渲染进程（宠物窗口、设置窗口）持有的是**只读副本**，只能通过 IPC 提交补丁、通过广播接收更新。这样避免"两个窗口各改一半、互相覆盖"。

### 4.2 配置文件结构

`config.json`（位于 `dataDir`）：

```jsonc
{
  "configVersion": 2,                 // 结构版本号，用于迁移
  "pet":    { "petName": "小银", "ownerName": "主人",
              "showNameInBubble": true, "size": 0.62 },
  "startup":{ "autoStart": false, "startHidden": true,
              "rememberPosition": true },
  "interact":{ "clickThrough": false, "wheelZoom": true,
              "hotkeyCall": "Ctrl+Shift+C", "trayDoubleClickCall": true },
  "sound":  { "muted": false, "volume": 70, "bubbles": true,
              "bubbleDuration": 2200, "notifications": false,
              "notifyInterval": 30 },
  "appear": { "theme": "light", "language": "zh-CN", "uiScale": 100,
              "opacity": 100, "showShadow": true, "showParticles": true,
              "reduceMotion": false },
  "behavior":{ "activityLevel": "normal", "callInterval": 75,
              "allowSleep": true, "allowRun": true },
  "data":   { "autoSave": true, "saveInterval": 5,
              "autoBackup": true, "backupKeep": 3 },
  "runtime":{ "x": null, "y": null,                     // 位置（高频）
              "stats": { "hunger": 80, "energy": 80, "happiness": 80 } }
}
```

改动要点：由现在的**扁平结构**升级为**分组嵌套结构**，语义更清晰；`dataDir` 本身**不存进 config.json**（否则形成"配置文件在哪里由配置文件决定"的循环依赖），而是记录在一个固定位置的引导文件 `bootstrap.json` 中（始终位于 `userData`）。

### 4.3 保存（写盘）策略

| 触发场景 | 写盘方式 | 防抖 / 节流 | 理由 |
|----------|----------|-------------|------|
| 开关、下拉、文本框（离散值） | 立即写 | 0 ms | 改动频次低，立刻落盘最稳妥 |
| 滑杆拖动（size / volume / opacity / uiScale） | 拖动中防抖 + 松手立即写 | 300 ms | 避免每秒数十次磁盘 IO |
| 窗口位置 `x/y` | 防抖写（已有实现） | 400 ms | 拖动过程高频产生 |
| 属性值 `stats` | 节流写 | `saveInterval`（默认 5 s） | 数值持续变化 |
| 设置窗口关闭 | 强制 flush | — | 保证不丢最后一次改动 |
| 应用退出 | 强制 flush | — | 保证不丢 |

**写入实现**：一律走"**原子写**" —— 先写 `config.json.tmp`，`fsync` 后 `rename` 覆盖。避免写盘过程中断电/被杀进程导致 JSON 截断损坏。

**备份机制**（`autoBackup = true` 时）：每次覆盖前把现有 `config.json` 复制为 `backup/config-<时间戳>.json`，保留最近 `backupKeep` 份，超出按时间滚动删除。

**并发保护**：主进程内的写操作排队串行执行（写队列 + 单一定时器），杜绝两个窗口同时写导致的内容交错。

### 4.4 读取、校验与迁移

启动时按序执行：

1. 读 `bootstrap.json` → 确定 `dataDir`；若目录不可用（不存在 / 是文件 / 不可写），回退默认目录并记日志；
2. 读 `config.json`；JSON 解析失败 → 把损坏文件另存为 `config.corrupt-<时间戳>.json`，用默认值启动，并在气泡/设置窗口顶部提示"配置已损坏，已恢复默认"；
3. **schema 校验与夹紧**：逐字段按类型转换（字符串→数字、`"true"`→`true`）、超范围夹回边界、非法枚举回退默认值。这一层保证"手工改坏配置也不会崩"；
4. **版本迁移**：`configVersion < 2` 时执行迁移函数（扁平结构 → 分组结构，旧 `size/stats/x/y` 原样搬入新分组），迁移前自动备份；
5. **未知字段保留**：不认识的字段原样留存并回写，保证向前兼容（例如用户手动挂了个未来版本的字段）。

## 五、生效时机（三类）

| 类别 | 判定依据 | 覆盖的设置项 | UI 表现 |
|------|----------|--------------|---------|
| **即时生效** | 主进程更新 `config` 后立刻通过 `config-changed` 广播；渲染进程订阅并应用 | 体型、主题、语言、不透明度、文字缩放、阴影、粒子、减少动效、静音、音量、气泡开关与时长、点击穿透、滚轮缩放、快捷键（重新注册）、活跃度、呼喊间隔、允许睡觉/奔跑、自动保存与备份、宠物名字与称呼 | 改动即见效果，无提示 |
| **重启生效** | 需要重建窗口/重读路径，仅落盘不热应用 | 数据存储位置 `dataDir`、静默启动 `startHidden`、单实例 `singleInstance` | 该项右侧橙色徽标 `重启后生效`，底部出现「立即重启应用」 |
| **下次登录生效** | 由操作系统登录项机制决定 | 开机自启动 `autoStart` | 勾选状态即时可见；提示文案"下次登录 Windows 时自动启动" |

## 六、进程间通信方案（新增 IPC 通道）

| 通道 | 方向 | 载荷 | 说明 |
|------|------|------|------|
| `get-schema` | 渲染 → 主 | — | 返回字段定义（类型/范围/默认值/生效类别/i18n key），设置窗口据此**动态生成表单**，避免 UI 与 schema 两处维护 |
| `open-settings` | 渲染 → 主 | — | 打开（或聚焦）设置窗口 |
| `get-config` | 渲染 → 主 | — | 已有，改为返回分组结构 |
| `save-config` | 渲染 → 主 | `{ 分组: { 字段: 值 } }` 补丁 | 已有，改为支持嵌套深合并 |
| `reset-config` | 渲染 → 主 | `{ keepPetName: bool }` | 恢复默认 |
| `export-config` / `import-config` | 渲染 → 主 | — / 文件路径 | 导出、导入（导入先返回差异预览，确认后再落盘） |
| `choose-data-dir` / `open-data-dir` / `migrate-data` | 渲染 → 主 | — | 选目录、打开目录、迁移并重启 |
| `restart-app` | 渲染 → 主 | — | 重启应用 |
| `config-changed` | 主 → 渲染（广播） | 完整 config + 本次变更的键路径 | 宠物窗口与设置窗口同时收到，双向同步（改滚轮 → 滑杆跟着动） |

**安全边界**：`preload.js` 只暴露上述具名方法，不透传任意通道；`import-config` 只读取用户通过系统文件对话框选中的路径，不接收渲染进程传来的任意路径，避免路径穿越。

## 八、边界条件与异常处理

| 场景 | 处理方式 |
|------|----------|
| `config.json` 被手工改坏（JSON 语法错误） | 另存为 `config.corrupt-<时间戳>.json` → 用默认值启动 → 顶部提示；**不静默丢弃用户数据** |
| 字段类型错误（如 `size: "大"`） | schema 校验层转换失败则回退默认值，并在设置窗口对应项显示"已恢复默认"提示 |
| 数值越界（如 `size: 5`） | 夹回 `[0.34, 0.88]`，不报错 |
| 枚举值非法（如 `theme: "rainbow"`） | 回退默认值 `light` |
| 宠物名字为纯空白 / 含控制字符 / 超 12 字符 | 输入框实时过滤控制字符、失焦 trim、超出长度截断，并红字提示；名字为空时回退默认名 |
| 快捷键被其他程序占用 | `globalShortcut.register` 返回 false → 回滚到上一个可用快捷键，气泡提示"快捷键被占用，已保留原设置" |
| `dataDir` 不存在 / 是文件 / 不可写 | 写入探针文件校验；失败则拒绝切换、保持原目录并提示具体原因 |
| 迁移数据目录中途失败 | 先复制后切换（copy → verify → switch）；失败时回滚为原目录，不删除源数据 |
| 导入的配置文件不合法 | 校验失败则拒绝导入并列出具体字段错误；合法则先展示差异预览，用户确认后才应用 |
| 系统不支持通知（`Notification.isSupported() === false`） | `notifications` 项置灰并提示"当前系统不支持通知" |
| 两个窗口并发写配置 | 主进程写队列串行化 + 单一防抖定时器 |
| 设置窗口已打开时再次打开 | 聚焦已有窗口并置顶到最前，不创建第二个实例 |
| 点击穿透开启后无法操作宠物 | 托盘菜单与快捷键仍可用；设置窗口「交互」组顶部常驻提示如何恢复 |

## 九、里程碑与验收标准

| 阶段 | 内容 | 验收标准 |
|------|------|----------|
| **S1** | `config-schema.js` + 主进程持久化（原子写 / 备份 / 校验 / 迁移）+ IPC | 无 UI 亦可脚本驱动：改任意字段 → 重启 → 值保持；改坏配置 → 自动恢复默认且生成 corrupt 备份 |
| **S2** | 设置窗口 UI（schema 驱动渲染 + 分组导航 + 校验反馈） | 34 项全部可见可改；改动即时反映到宠物窗口；滑杆拖动不卡顿、不刷爆磁盘 |
| **S3** | i18n + 主题 + 数据目录（选择 / 迁移 / 重启）+ 导入导出 | 双语切换即时生效；改目录后重启数据仍在新目录；导出文件可被导入并完整还原 |
| **S4** | 测试扩展 + 真实运行验证 | `test_logic.js` 断言全绿；真实运行下逐项手工验证并录屏留证 |

**总体验收**：

1. 任意时刻双击托盘/右键菜单都能打开设置窗口，且不会出现第二个窗口实例；
2. 全部 P0 项均可正常读写，越界值一律夹紧且不崩溃；
3. 重启应用后所有设置（除明确标注"下次登录生效"的项）完整恢复；
4. 删除/改坏 `config.json` 后仍能正常启动，并给出可读提示；
5. 数据目录可迁移，迁移后原数据不丢失。
