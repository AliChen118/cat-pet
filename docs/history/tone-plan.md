# 喵叫音色统一方案（tone-plan）

> 目标：29 条语音素材整体呈现**可爱、温柔**的特质，去掉尖锐/刺耳/毛刺感，
> 同时**保住真实录音的自然细节**（气声、共振峰、颤音、呼噜），不做降噪、不加混响、不做机械式均衡。
> 基线：语音阶段 2 的 29 条 CC0 真实录音（OGG，258 KB）。加工脚本：`tools/audio/import_meows.py`。

---

## 一、什么样的声音算"刺耳"，以及怎么量化

人耳对**2–5 kHz** 最敏感（外耳道共振 + 听觉神经密集区）。猫叫的"尖"通常来自两处：

| 成因 | 听感 | 客观指标 | 本方案的处理 |
|---|---|---|---|
| 3–5 kHz 谐波堆积（尤其明亮的小猫音） | 扎耳朵、听久了累 | `3–5k 能量占比`、`Zwicker 尖锐度` | 3.4 kHz 定点削 + 5.6 kHz 高频架 |
| 起音瞬态过冲（波形第一个峰比平均响 15 dB 以上） | "炸"、"咔"、点击声 | `峰值 − RMS`（crest factor） | 温和峰值压缩 + raise-cosine 起音 |
| 6 kHz 以上毛刺 / 嘶声 | 沙、刺、脏 | `>6k 能量占比` | 11 kHz 低通 + 高频架 |

两条判据（本次验收线）：

- **Zwicker 尖锐度 ≤ 1.30 acum**（原 4 条超 1.39，最高 1.59）
- **3–5 kHz 占比 ≤ 4%**（原最高 13.4%）
- 同时 **1–3 kHz 存在感保留 ≥ 75%**——防止"削刺"削成"闷哼"（这是最容易翻车的地方）

## 二、统一处理链

```
源 WAV/OGG → 单声道 44.1k → 切片 → 裁静音（留 10ms 前导）
           → 高通 90Hz（去直流/低频轰鸣）
           → 重采样变速（定音高与时长，音高↔时长天然耦合）
           → 【音色层】4 段 EQ：加暖 → 补实体 → 削刺 → 削嘶
           → 【动态层】温和峰值压缩（只压瞬态尖峰）
           → 柔性起音/收尾（raise-cosine）
           → 响度归一（分档 RMS）+ 软限幅（tanh，只在峰值样本上）
           → OGG/Vorbis
```

### 为什么这样设计（每步解决什么）

| 环节 | 参数 | 解决 | 为什么不更狠 |
|---|---|---|---|
| 320 Hz 低架 | **+2.6 dB** | 胸腔厚度，让叫声不"薄" | 超过 +4 dB 会糊成一团、丢失"喵"的锐度 |
| 900 Hz 峰 | **+1.2 dB** | 补实体感，抵消削高频后的"虚" | 超过 +3 dB 变鼻音 |
| 3.4 kHz 峰（Q 1.15） | **−3.4 dB**（个体 −1.0 ~ −6.6） | 刺耳主区 | 削到 −8 dB 会让"喵"变成"呜" |
| 5.6 kHz 高频架 | **−4.2 dB**（个体 −2.0 ~ −7.2） | 嘶声、毛刺 | 深架会把气声细节一起抹掉 |
| 11 kHz 低通 | 二阶 Butterworth | 超高频毛刺（猫叫本身在此以上几乎无内容） | 不做 brickwall，保住瞬态锐度 |
| 压缩 | 比 **2.6:1**，阈值 = RMS+2.5 dB，attack 10 ms，release 120 ms | 只压住峰值（crest 从 19.6 降到 14.8） | 比 4:1 更狠会压扁气声与颤音 → "机械感" |
| 起音 | **12–20 ms raise-cosine** | 起音点击 | 线性 6 ms 仍有 click；超过 25 ms 会吃掉起音的"启动感" |
| 响度 | normal −18 / soft −20.5 / urgent −15.5 / sys −20 dBFS | 29 条音量齐平 | 削峰用 tanh 只作用于 <0.5% 采样，不整体缩放 |

**没有做的事（为了"自然"）**：不做降噪、不做频谱修复、不做激励/饱和、不加混响、不做音量自动化、不做相位声码器移调。

### 分组设计意图

**A. 最尖两条（`play_2` / `hungry_2`，源自"明亮高音小猫"）**
音高最高、3–5k 占比 12–13%，是"刺耳"的主要来源。
处理：**降调 0.09/0.07 + 削刺加深到 −6.6 dB + 削嘶 −6.2 dB**。
降调把第 3/4 谐波从 3.5–4.7 kHz 挪回 3.2–4.3 kHz 并降低谐波密度；
同时保住 92% 的 1–3k 存在感（反而 +11%，因为削走高次谐波后基频相对更突出）→ 更"奶"而不"闷"。

**B. 已很暖的四条（`eat_2` / `pet_3` / `tired_2` / `wake_2`，含呼噜）**
200–500 Hz 占比本来就有 42%，再按统一量加暖会变成"糊成一团"。
处理：**加暖只给 +0.8 dB（统一值的 1/3）、削嘶只 −2.0 dB、削刺 −2.4 dB**。
这是唯一一组"减配"的，目的就是防止闷。

**C. 高音轻喵两条（`pet_2` / `idle_1`，f0 ≈ 940–960 Hz）**
原素材一点都不尖（3–5k ≈ 0%），但对它们套统一曲线会把第 3/4 谐波削掉，
实测 1–3 kHz 存在感一度掉 31%——**"喵"会变成"呜"**。
处理：**削刺只给 −1.0/−1.2 dB、加暖降到 +1.4 dB**，存在感回到 −21%（其余靠削嘶保持柔和）。

**D. 系统音（`sys_1` / `sys_2`）**
只需要辨识度，不需要表现力。处理：**低通收到 9k/8k、削刺 −5.8/−6.5 dB、削嘶 −6.7/−7.2 dB、起音 18–20 ms**。
0.14–0.17 s 的短促"喵"变成柔和的"提示感"，不会在连续操作时扎耳朵。

**E. 危急喵（`urgent_1` / `urgent_2`）**
需要"急"但不能"尖"。处理：**紧迫感靠短促（0.35/0.38 s）+ 峰值 −2 dBFS，而不是靠高音——降调 0.10/0.05 后只比普通喵高 5%。**

**F. 其余（抚摸/进食/洗澡/唤醒/呼喊/低落/脏乱/孤独）**
统一参数 + 小幅降调（−0.02 ~ −0.13），仅按各自尖锐度追加 −0.4 ~ −1.9 dB 削刺。

## 五、复跑、微调、回滚

```bash
# 重生成全部素材（改 TARGETS / RATE_ADJUST / TONE_PER 后执行）
python tools/audio/import_meows.py

# 客观测量（前后对比；--csv 输出明细）
python tools/audio/analyze_meow_tone.py --csv _after_meow.csv

# 试听页（单文件自包含，29 条内嵌）
python tools/audio/make_meow_preview.py

# A/B 对比页（旧素材 vs 新素材，含指标对照）
python tools/audio/make_meow_ab.py
```

**想更柔**：把 `TONE_PER` 里对应条目的 `harsh` 再减 1–2 dB（不要超过净 −8 dB，否则"喵"会变成"呜"）。
**想更亮**：把 `harsh` 加 1 dB；`sibil`（5.6k 架）比 `harsh` 更影响"清亮感"，优先动它。
**想更"奶"**：把 `RATE_ADJUST` 再减 0.02–0.03（时长会相应变长，注意 `sys`/`urgent` 的时长上限）。

**回滚**：`_backup/tone-pre_<时间戳>/meow/` 是柔化前的完整 29 条，整目录覆盖即可还原。

## 六、已知取舍

1. **`sys_2` 尖锐度仍 1.29**：它是 0.14 s 的极短音，短窗频谱分辨率有限，指标天然偏高；实际 3–5k 只有 0.8%、且低通到 8 kHz，听感不会刺。若要继续降只能牺牲提示音的辨识度。
2. **`play_2` / `hungry_2` 的 3–5k 仍有 3.4–3.6%**：这是"兴奋/讨食"该有的明亮度。再削会失去情绪，故保留。
3. **降调幅度的边界**：`hungry_2` 已降 7%，再降会让它和 `hungry_1` 的音高关系错位（同一情境两条应接近）。
4. 本方案**未改动**源素材与许可证信息，只改加工参数；`CREDITS.md` 已同步。
