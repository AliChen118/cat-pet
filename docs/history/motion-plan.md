```js
const ACTIVITY = {                       // 权重表 —— 存在明显偏向
```

### 0.3 尺寸形变现状（`renderer.js` `computeMods()` → `animator._drawOne()`）

`animator.js:214-215` 直接把形变量乘进画布缩放：

```js
const sx = s * (mods.squashX || 1);
const sy = s * (mods.squashY || 1);
```

`computeMods()` 里所有 `squashX/squashY` 写入点，**全部会改变宠物渲染尺寸**：

| 位置 | 形变量 | 视觉表现 |
|---|---|---|
| `idle` | Y +0.6%、X −0.6%（心情好 ±0.66%） | 呼吸时轻微拉高变窄 |
| `sleep` | Y ±0.8% | 呼吸起伏 |
| `bath` | Y ±0.8% | 水面起伏 |
| **`unhappy`** | **Y ±1.2%** | **用户点名的"伤心动作变大变小"** |
| **落地挤压**（jump/fall 落地） | **Y ×(1−0.35·s)、X ×(1+0.30·s)** | **最大 −35% 矮 / +30% 宽，最明显的一处** |

> 注：`bob`（垂直位移）与 `tilt`（旋转）**不改变尺寸**，不在本次整改范围。
> 帧序列素材本身由 `normalize_sequence.py` 按**全序列统一比例**缩放，不会逐帧大小跳动。

### 0.4 设置页应用/取消现状（`settings.js`）

```js
$btnApply.addEventListener('click', () => { …api.saveConfig(patch).then(() => { renderFooter(); flash(T('saved')); }); });
$btnCancel.addEventListener('click', () => { …api.saveConfig(groupPatchOf(revert)).then(() => { …; flash(T('discarded')); }); });
```

## 1. 需求一：帧数翻倍（≈2×），动画更流畅

### 1.1 目标帧数表

采用**「相邻帧之间插入 1 张过渡帧」**策略：循环动作首尾相接也插 1 张 → 恰好 **2.00×**；单次动作（jump / stretch）两个间隙各插 2 张 → 2.33×，跳跃感最需要流畅。

| 姿态 | 现有 → 目标 | 新增张数 | FPS 现有 → 目标 | 单周期时长 |
|---|---|---|---|---|
| idle | 4 → **8** | +4 | 5 → 10 | 0.80s（不变） |
| walk | 4 → **8** | +4 | 11 → 22 | 0.36s（不变） |
| run | 4 → **8** | +4 | 13 → 26 | 0.31s（不变） |
| tailwag | 4 → **8** | +4 | 7 → 14 | 0.57s（不变） |
| eat | 4 → **8** | +4 | 6 → 12 | 0.67s（不变） |
| play | 4 → **8** | +4 | 8 → 16 | 0.50s（不变） |
| bath | 6 → **12** | +6 | 6 → 12 | 1.00s（不变） |
| pet | 3 → **6** | +3 | 6 → 12 | 0.50s（不变） |
| meow | 3 → **6** | +3 | 7 → 14 | 0.43s（不变） |
| sleep | 3 → **6** | +3 | 4 → 8 | 0.75s（不变） |
| unhappy | 2 → **4** | +2 | 2 → 4 | 1.00s（不变） |
| jump | 3 → **7** | +4 | 5 → 10 | 单次动作 |
| stretch | 3 → **7** | +4 | 5 → 10 | 单次动作 |
| **合计** | **47 → 96** | **+49** | — | 平均 **2.04×** |

**关键原则：帧数翻倍的同时帧率同步翻倍 → 动作时长与节奏完全不变**，只是把"跳帧感"换成"补间感"。用户设置的「动作速度」`animSpeed` 仍在其上叠乘，不受影响。

### 1.2 生成方式（沿用已验证的管线）

1. **逐张 ImageGen 生成**（禁止并发，避免输出文件名时间戳碰撞丢帧）：
   - 入参：`image1` = 前一张帧、`image2` = 后一张帧（工具支持 1–3 张参考图）
   - `input_fidelity: "high"`
   - 提示词强调：`flat solid pure magenta background, no gradient, same chibi silver-shaded longhair kitten, same proportions/scale/facing, single cat centered, intermediate pose between the two reference frames`
2. **抠图**：`tools/sprites/extract_sprite.py`（自动剔除水印；候选像素须与主体最大连通域保持距离）
3. **序列归一化**：`tools/sprites/normalize_sequence.py` —— 全序列统一缩放 + 躯干 IoU 对齐，杜绝大小跳动与横向抖动
4. **边界校验**：`tools/sprites/sprite_bounds.py` 确认全帧半宽 ≤ `SPRITE_HALF_W = 253`；超过则回退重生成该帧
5. **更新 `CONTENT_TOP_FALLBACK`**：新序列内容顶边会变化（现多为 130，walk/run/tailwag/unhappy/drag 为 70），按 `sprite_bounds.py` 实测值更新
6. **预览确认**：生成后先出「原帧 / 补间帧」对照预览图（gif 或拼图）给你过目，再入库

### 1.3 同步改动清单

| 文件 | 改动 |
|---|---|
| `renderer.js` | `SPRITE_FILES` 各姿态帧数组扩到新张数；`SPRITE_FPS` 按上表翻倍 |
| `engine/animator.js` | `CONTENT_TOP_FALLBACK` 更新；`FRAME_BLEND = 0.35` 保持不变（帧更密 + 淡化 = 更顺；若出现"糊"，降到 0.25） |
| `tools/check/test_logic.js` | `EXPECTED` 帧清单 47 → 96，断言同步 |
| `cat-pet/README.md` | 帧数表、目录树（"13 个序列帧姿态，96 张帧"） |
| 素材目录 | 顺带清理 8 张陈旧副本 `walk1-4.png` / `run1-4.png` |

### 1.4 成本与风险（需要你知情）

- **ImageGen 消耗**：49 张 × 每张约 5–10 积分 ≈ **245–490 积分**（工具按张计费，这是独立于订阅的额外开销）
- **单张耗时**：约 15–40 秒，逐张串行 ≈ **15–30 分钟**，我会分批推进并随时报进度
- **质量风险**：AI 补间帧可能与前后的腿部/尾巴位置不完全吻合。缓解手段 = IoU 对齐 + 边界校验 + **先生成 2 个姿态（walk / unhappy）做小样验证**，你看过效果满意再铺满全部 13 个姿态

## 2. 需求二：活动状态下动作「完全随机」，无固定顺序与权重偏向

### 2.1 问题定位

不是"有固定顺序"，而是**权重偏向**让 walk 长期占 36%，主观感受成"一直走"。修正 = **基础分布拉平为等概率**。

### 2.2 方案：等概率池 + 属性只做「修正」不做「基础偏向」

```
基础池（等概率，各 1/6）：walk、run、jump、stretch、idle(坐)、tailwag
```

- **四项属性全部正常时** → 六种动作各 **16.7%**，纯粹的完全随机；
- **属性出现异常档位时** → 仍由 v1.7.0 的 `combineWeights` 施加乘子（保持你上一轮确认的行为联动）：
  - 饿了 → run / jump 硬否决（0），多喵叫讨食
  - 脏了 → tailwag 硬否决（0）、少跑、多蔫着
  - 心情好 → run / tailwag 提升
- **`meow`（喵叫）不进等概率池**：它保留由「长时间无互动（`callInterval`）」与「危急需求」单独触发。理由：若把 meow 摊成 1/7 ≈ 14%，猫会频繁叫唤+刷气泡，观感吵。
- **`unhappy`（伤心）不进等概率池**：由心情档位驱动（心情低/危急时触发），保持"伤心动作只在心情差时出现"的语义。
- **`activityLevel`（安静/标准/活泼）保留差异的维度改为**：决策间隔 `think`（4.5–9.0s / 2.2–5.5s / 1.2–3.2s）+ 趴睡倾向偏移（+15 / 0 / −20），**不再影响动作分布**。

### 2.3 待确认的歧义

- 需求原文举例含**「坐」**，但当前素材库**没有独立的 "sit" 姿态**（只有 idle 的坐姿待机）。本方案将 **idle 视为「坐」**。若你要一个独立"坐下"动作（从站到坐的姿态），需**新增 1 个姿态素材（+4 张帧）**，请明确。

### 3.2 取消（回滚）

`取消` 是**破坏性操作**，必须二次确认：

- 存在未保存改动 → 弹出确认框（复用现有 `#overlay` 弹层，改造为通用确认框）：
  > **放弃 N 项未保存的更改？**　[继续编辑] [放弃更改]
- 确认后 → 回滚 + toast `已还原为上次保存的设置`
- 无改动时按钮保持 `disabled`（现状不变）

### 3.3 未保存状态可见化

- 底栏新增 `● N 项未保存的更改`（与"需重启项"警告并列显示）
- 关闭设置窗口（点 × / `Escape`）时若存在脏值 → 拦截并弹同一个确认框，避免静默丢弃

## 4. 需求四：动作播放全程宠物尺寸恒定

### 4.1 整改原则

> **所有程序化形变只能改变「位置（bob）」与「角度（tilt）」，不得改变「尺寸」。**

### 4.2 逐项处理

| 序号 | 现有形变 | 处理 |
|---|---|---|
| 1 | `unhappy` 的 `squashY/X ±1.2%`（伤心动作） | **删除**，只保留 `bob` 的下沉起伏 |
| 2 | `idle` 的 `squashY/X ±0.6%`（含心情好 ±0.66%） | **删除**；"心情好"的正反馈改由**加大 `bob` 幅度**表达 |
| 3 | `sleep` 的 `squashY/X ±0.8%` | **删除**（帧序列本身已含呼吸起伏） |
| 4 | `bath` 的 `squashY/X ±0.8%` | **删除**，只保留水面 `bob` |
| 5 | **落地挤压** `squashY×(1−0.35s) / squashX×(1+0.30s)` | **删除**；改为**落地"下蹲"位移**：落地瞬间 `bob` 下压约 6px 后 0.25s 内弹回。保留"咚"的打击感，但**零尺寸变化** |
| 6 | `walk/run` 的 `bob`、`tilt` | **保留**（位移 + 旋转，不改尺寸） |
| 7 | `jump/fall/drag` 的 `tilt` | **保留** |
| 8 | 帧序列素材本身 | 天然统一比例（`normalize_sequence.py` 保证），无需改动 |

### 4.3 回归防线

新增断言：遍历全部 13 个状态，断言 `computeMods()` 返回值恒满足
`squashX === 1 && squashY === 1 && scaleMul === 1`，任何未来改动若重新引入尺寸形变会立刻红灯。

> 说明：帧序列里猫的*姿势*（趴下、伸懒腰）本身会占用不同的画面高度，这属于**素材姿态**而非"改变大小"，不在整改范围。

## 5. 边界情况处理

| 场景 | 处理 |
|---|---|
| 帧数翻倍后拖动窗口 / 缩放体型 | 无影响（帧只影响画面，不影响命中区与边界计算） |
| `reduceMotion = true` | 帧序列照常播放（帧数更多 ≠ 更多动态），形变量本就已归零 |
| `animSpeed` 调慢/调快 | 帧率翻倍在后，`animSpeed` 乘在前，两者独立，时长按 `1/animSpeed` 变化 |
| 属性全正常 + `needVoice=false` | 仍为等概率池（分布与语音无关） |
| 自定义 `activityLevel` | 只改决策间隔与趴睡倾向，不改动作分布 |
| 脏值 + 点「应用」失败 | 按钮不置灰、toast 报错，脏值保留可重试 |
| 设置窗口有脏值时 `Escape` | 弹确认框，取消则留在窗口 |
| 补间帧半宽 > 253px | 该帧回退重生成（`sprite_bounds.py` 卡口） |

## 6. 实施顺序与验收

1. **素材小样验证**：先补 `walk`（+4）与 `unhappy`（+2）→ 出对照预览 → **你确认后再铺满其余 11 个姿态**

3. `renderer.js`：`SPRITE_FILES` / `SPRITE_FPS` 更新；`ACTIVITY` 改为等概率池
4. `renderer.js`：`computeMods()` 移除全部尺寸形变 + 落地改位移下蹲
5. `settings.html` / `settings.js` / `i18n.js`：应用/取消反馈交互
6. `tools/check/test_logic.js`：帧清单 47 → 96、等概率分布断言、尺寸恒定断言、脏值确认流程断言
7. 全量回归（目标 ≥150 断言，连续多轮无 flaky）+ 数值沙箱（等概率分布卡方检验）
8. 实机冒烟 → 升版 **1.8.0** → 打包 portable + nsis → 更新 README 与项目记忆

**验收标准**：帧数 ≥1.9×、动作时长不变；属性正常时六种动作分布显著均匀；应用/取消均有可见反馈且取消有二次确认；全程 `squashX/squashY` 恒为 1。

## 7. 需要你拍板的 6 点

| # | 问题 | 我的建议 |
|---|---|---|
| 1 | 帧率是否**同步翻倍**（保持动作时长与节奏不变）？ | 是。否则动作会变"慢动作" |
| 2 | 是否接受 **ImageGen 约 245–490 积分 / 15–30 分钟**的成本？ | 建议先做 walk+unhappy 小样（约 6 张、30–60 积分）验证效果再全量 |
| 3 | `meow`（喵叫）是否排除在等概率池外（避免频繁叫唤）？ | 建议排除，仍由"长时间无互动/危急需求"触发 |
| 4 | 需要独立「坐（sit）」姿态吗？还是沿用现有 idle 坐姿？ | 建议沿用 idle，零新增素材 |
| 5 | 落地挤压是否接受改为「**下蹲位移**」版本（保留打击感、零尺寸变化）？ | 建议接受；若你要更"平"，可直接完全删除落地动效 |
| 6 | 应用反馈是否需要**宠物也冒气泡**（"设置已保存～"）？ | 建议要，反馈更直观 |
