## 三、播放器与插值

`engine/animator.js` 是一个只认帧序列的播放器，不理解"状态"——状态切换由 `renderer.js` 的 FSM 调 `play()` 驱动。

```js
animator.play(name, fade = 0.18, { once, startAt })
animator.update(dt)      // 推进帧与过渡
animator.draw(ctx, { x, y, scale, facing, mods })
animator.contentTop()    // 当前帧内容顶边（气泡定位）
```

**交叉淡化**：`FRAME_BLEND = 0.35`——每帧时段的**后 35%** 与下一帧做交叉淡化，曲线 `Core.Ease.inOutQuad`。即播放 `frames[i]` 的同时叠加 `frames[i+1] × k`（k 由 0 升到 1）。效果等效于把 4 帧循环"加密"成连续过渡，肉眼几乎看不到帧跳变。

**姿态切换**：`fade = 180ms` 双姿态叠加（旧姿态淡出、新姿态淡入），同锚点对齐，不会整体位移。

**防丢帧**：帧推进用 `while` 循环最多补 16 步，低帧率/卡顿环境下动画时长仍与真实时间一致。

> **关键工程判断**：不要用"往素材里塞透明叠加帧"来提升流畅度。运行时已有 35% 交叉淡化，再叠加逐像素等价，只会白吃包体与启动时间。要让加帧有价值，新增帧必须携带**新的运动信息**。（这条结论来自一次失败尝试，见 `history/frames-plan.md`。）

## 四、待机眨眼

眨眼**不挂在帧序列上**，由一条独立累加时钟驱动（`blinkCfg` / `_scheduleBlink`），否则会被帧循环绑成固定节拍。

```
blinkCfg = { active:[0,3], blinkFrame:2, meanGap: 60/blinkRate }
```

| 规则 | 行为 |
|---|---|
| 常态 | 只在两帧睁眼之间轮播（`idle_1` ↔ `idle_4`）；困倦半闭的 `idle_2` **退出循环** |
| 眨眼 | 到点硬切入闭眼帧 `idle_3`，定格 1 帧时长（0.2s），末端 35% 插值淡回原睁眼帧 |
| 随机 | 每次眨完重排：`meanGap × (0.55 + rand × 0.9)`，即 **±45% 均匀抖动**，去掉固定周期感 |
| 频率变更 | `gapSeen` 检测到 `meanGap` 变化 → 立即作废旧周期重排（8 次/分改成 30 次/分，0.8s 内就会眨第一下） |
| 频率 0 | `meanGap = 0` → 完全不眨眼 |
| 打断 | `play()` 切走非 `idle` 时清 `blinkHold`，不会卡在闭眼 |
| 后端兼容 | `blinkCfg === null` 时退回旧的整序列 4 帧循环（无头测试与旧调用路径仍可用） |

设置项：`behavior.blinkRate`（0–30 次/分钟，默认 8，0 = 不眨眼），经 `config-changed` 实时生效。

> 两个必须守住的不变量（都曾因重写 `update()` 而破功）：① 普通分支必须保留 `frameTime += dt`，否则非 idle 姿态的帧永不推进（表现为"所有动作都只剩第 1 帧"）；② 首次进入 idle 必须把 `blinkAt` 从 `Infinity` 排掉，否则永远不眨眼。

**逐帧停留**（`play(name, fade, { hold: { 帧索引: 秒 } })`）：普通分支的推进时长由 `frameDur(frameIndex)` 给出——命中 `hold` 用覆盖值，否则用 `1/fps`。目前只有 `lick` 用它把主帧 `lick_2`（索引 1）拉到 `1/5 + 0.15 = 0.35 s`，其余姿态 `holdMap` 为 `null`，行为与原来完全一致。眨眼分支仍用基础 `dur`，不受影响。

**帧间插值的两个硬性约束**（2026-10-25 修复，均曾导致舔爪残影）：

1. 插值窗口必须按**该帧实际停留时长**算，不能用 `1/fps`。否则被 `hold` 拉长的帧会让进度 `t` 越过 1，`inOutQuad` 回落成负值——下一帧先满不透明地盖上（200 ms 处）、再反向淡出（205–342 ms）、最后硬切到它自己，视觉上就是「闪一下又没了」的残影。现由 `frameDur(name, idx)` 统一提供时长，且 `t`、`k` 都夹取到 `[0,1]`。
2. 插值实现是「当前帧实心 + 下一帧按 `k` 叠上去」，差异大的序列会产生两个轮廓同时可见的双影。判据是**相邻帧 alpha 掩膜最小 IoU < 0.90**。1.1.10 全量复测后，`NO_FRAME_BLEND` 扩到 10 个姿态：

   | 姿态 | 最小相邻帧 IoU | 不硬切会看到什么 |
   |---|---|---|
   | run | 0.59 | 四条腿、两条尾巴 |
   | jump | 0.68 | 两副前爪、两条尾巴 |
   | walk | 0.69 | 四条腿 |
   | stretch | 0.75 | **两个头、两张嘴、两条尾巴** |
   | tailwag | 0.77 | 两条不同位置的尾巴 |
   | bath | 0.79 | 两副耳朵、双份水面与泡沫 |
   | unhappy | 0.80 | 两个头轮廓、泪珠虚影、双份前爪 |
   | play | 0.82 | **两只红球**（一实一虚，位置差 40 px） |
   | eat | 0.84 | **两个食盆** |
   | lick | 0.86 | 双爪 / 双头 |

   保留插值的是差异小的四个：`sleep` 0.94、`pet` 0.94、`idle` 0.98、`meow` 0.99。
   **新增姿态时先跑 `tools/check/pose_iou.py`，<0.90 就加进集合**，否则一定出现残影。

## 五、体型与形体

| 量 | 值 | 含义 |
|---|---|---|
| `SIZE_100` | 0.88 | 界面显示的 100% 基准 |
| `MIN_SCALE` / `MAX_SCALE` | 0.18 / 0.88 | 显示 20%–100% |
| `SCALE_STEP` | 0.04 | 滚轮每格 5% |
| `BASE_SCALE` | 0.62 | 阴影半径、命中区等实测比例参考 |

**三处共享同一状态**：设置页滑杆、滚轮缩放、菜单放大缩小改的是同一个 `pet.size`，任一入口改动即时同步；越界夹回并给气泡提示（"已经是大喵形态啦"）。

**姿态缩放**：`POSE_SCALE = {}`——**空表**。1.1.10 起全部 15 个姿态的比例都已烘焙进素材，运行期系数恒为 1，进出任何姿态**没有任何尺寸过渡**。表与 `poseCur` / `posePrev` 平滑机制保留，仅作应急兜底（新增姿态时优先改素材）。

**姿态尺寸一致性（1.1.10 一次性统一）**：由 `tools/sprites/fix_pose_frames.py` 一次跑完，每帧固定三步：

1. 绕锚点 `(256, 470)` 等比缩放 `k`（只有 `k≠1` 的姿态才动）；
2. 平移 `dx` 使**腐蚀核心质心 x = 256**（与全库其余姿态的口径一致）；
3. 平移 `dy` 使**内容底边 = 469**（全库统一）。

脚本只允许跑一次（二次变换会累积），原始帧备份在 `_backup/pose-fix-orig/`（已 gitignore）；也可以直接 `git show <上一提交>:app/assets/sprites/frames/<帧>.png` 取回。

|---|---|---|
| `walk` | 0.930 | 侧视站立：面积 108%→94%，同时换取横向对位余量（把 0 px 提到 5 px） |
| `drag` | 0.930 | 与 `walk` 同尺度（同为侧视站立），缩放后两者高度 371/371 完全一致 |
| `run` | 0.900 | 侧视奔跑：面积 120%→97%，同样换取对位余量 |
| `bath` | 0.943 | 眼距中位数 102.0→96.2；**替掉了原来的运行时 `POSE_SCALE=0.87`** |
| `jump` | 1.056 | 立方根均衡，见下 |
| `play` | 1.093 | 立方根均衡，见下 |
| `lick` | 1.072 | 眼距 93.3%→97.3% |
| `meow` | 1.030 | 眼距 97.1%→99.7% |
| `tailwag` | 0.995 | 眼距 100.5%→100.2% 微调 |
| 其余 6 个 | 1.000 | `idle`（基准）、`stretch`/`sleep`/`eat`（侧视，面积已在 93–97%）、`pet`（已按面积口径烘焙且闭眼帧眼距不可靠）、`unhappy`（已按底边锁高口径烘焙） |

结果：15 个姿态的**内容底边全部 = 469**、**躯干质心极差 ≤0.8 px**、**面积落在 idle 的 93–113%**（`bath` 110% 含浴盆、`drag` 105% 为侧视站立）、**横向余量最小 5 px**。

- **`jump` / `play` 是「头小身大」的素材，等比缩放只能二选一。** 实测头（眼距与耳距两个口径一致）只有 idle 的 84–87%，但身高已齐平、整幅面积已 101%/91%。等比拉到头对齐会让整体面积飙到 **142%/129%**（猫肉眼可见地膨胀一圈）；反过来完全不缩放又让脸小 16%。因此取**立方根均衡系数** `k=(1/(eye·area))^(1/3)`，让两边的对数偏差相等：头修到 89%/92%、整体 112%/109%，各偏 8–12%。**彻底解决需要重画这两组素材。**
- `bath` 的 `k` 用**中位数**而不是均值：`bath_2` 是闭眼帧，eye_gap 测到 112.2 px（闭眼弧线两端比眼球中心更靠外），会把均值拉到 104.0；去掉它之后 5 帧是 101.3–102.4，中位数 102.0。
- **为什么 `walk`/`run` 不重跑 `normalize_sequence.py`**：它的躯干模板匹配以序列首帧为模板，而 `run_1`（收腿竖直）与 `run_2`（铺平伸展）腐蚀 10 次后的核心形状完全不同，模板匹配给出的位移本身就是错的（实测矫正后质心极差仍有 20 px）。直接钉质心更稳 —— 全库其余 12 个姿态的质心本来就落在 255.5–256.5，这才是项目的实际口径。`normalize_sequence.py` 现在只作为「手绘序列首次入库」的工具。
- 历史口径经验（仍然有效，供新增姿态时选判据）：**眼距**是首选（刚性、不受尾巴干扰，但闭眼/侧脸帧测不到）；**整幅 alpha 面积**适合「无高举大尾巴、无肢体大位移」的姿态（`pet` 用它，但对 `tailwag`/`walk`/`run` 会被尾巴污染）；**底边锁高**适合前腿下垂、尾巴绕身的姿态（`unhappy` 用它）；**躯干带核心面积**在体宽超过 132 px 时**测量饱和**，不可用（`unhappy` 体宽 321 px 就是反例）。

**帧级平滑**：体型与姿态系数不做瞬时切换。`updateScaleSmoothing(dt)` 用指数趋近（`SCALE_SMOOTH = 0.0004`，每帧收敛 12%、时间常数约 0.14 s，到位约 0.4 s）维护 `sizeCur` / `poseCur` / `shadowKCur`，首帧直接 snap。

> **`draw()` 的 `mods` 复用坑（1.1.10 已修）**：淡化期（`blend < 1`，默认 0.18 s）里退场的旧姿态过去会拿到**已切到新姿态的** `poseCur`，导致旧画面在仍可见时被缩放。现在 `computeMods()` 额外输出 `prevScaleMul: posePrev`（切姿态那一刻定格旧值），`animator.draw()` 对 `prev` 用 `Object.assign({}, mods, { scaleMul: mods.prevScaleMul })` 重算。当前 `POSE_SCALE` 为空，这段逻辑是纯防御。

**阴影随姿态缩放（1.1.10 新增）**：`POSE_SHADOW_K` —— 各姿态身体占地在 269–465 px 之间浮动（±27%），固定半径的阴影在 `run`/`walk` 这种铺平姿态下明显偏小（猫像浮在影子上），`sleep` 蜷起来时又偏大。系数 = `sqrt(该姿态腐蚀核心面积均值 / idle)`，范围 0.946–1.066，由 `tools/sprites/sprite_bounds.py` 一并生成（改素材后必须重跑）。平滑值 `shadowKCur` 与体型同频。

> **改几何代码时的铁律**：绘制、阴影、食碗、气泡、特效一律读平滑值（`sizeCur × poseCur`），逻辑量（活动边界、命中判定、面板位置）仍读 `pet.size`。直接读 `poseScale()` 或 `pet.scale` 会造成单帧跳变（历史实测 0.114 的突跳）。

**只允许改位置和角度，不允许改尺寸**：`computeMods()` 只产出 `bob`（垂直位移）、`tilt`（旋转）、`alpha`。`squashX/squashY` 恒为 1——尺寸形变会让"猫忽大忽小"，落地挤压改为下蹲位移表达。测试里有遍历全状态的断言守着。

**避免双重动画**：帧序列本身已含肢体运动，walk/run 的程序化起伏被收敛（walk bob 4→2.4、tilt 0.035→0.02；run bob 6→3.2、tilt 0.06→0.04），否则二者打架产生抖动。

## 六、气泡与阴影

**气泡**：

- 每帧挂在猫头顶正上方，间距 2px，**尺寸固定不随体型缩放**（字号由 `appear.uiScale` 控制），任何体型下都可读；
- 头顶纵向位置由 `animator.contentTop()` 实测 + 指数平滑，消除帧切换的微抖；
- 尖角始终指向猫头：气泡被窗口边缘夹紧时，靠 CSS 变量 `--tail-x` 横向偏移尖角；
- 宠物窗口贴屏幕边缘时气泡自动改为向内展开。

**阴影**：椭圆圆盘半径 = `当前体型 / 设计基准` 等比缩放，并按离地高度同步淡出收缩，始终与猫脚接触面匹配。

> 历史根因：`_drawOne` 里 `drawImage` 的宽高曾重复乘了一次缩放系数（`ctx.scale` 已缩放过），导致实际渲染是 `scale²`——猫比设计尺寸小一圈，气泡"离猫很远"、阴影比例失调。代码里保留注释提醒不要重复相乘。

## 七、素材生成管线

素材全部由 AI 生成后经脚本处理，脚本在 `tools/`：

| 脚本 | 作用 |
|---|---|
| `extract_sprite.py` | 四角采样推背景色 → 颜色距离掩码 → 仅保留边界连通背景 → 去平台水印 → 腐蚀 + 高斯模糊柔边 |
| `normalize_sprite.py` | 裁剪内容边界 → 等比缩放到目标高度 → 贴回 512×512 并对齐地面基线 |
| `normalize_sequence.py` | **整序列**统一缩放（禁止逐帧各自缩放，否则大小跳动）+ 以首帧躯干核心做 IoU 水平对齐 |
| `sprite_bounds.py` | 实测各帧内容顶边与最大半宽 → 生成 `CONTENT_TOP_FALLBACK`；半宽超 253 即报错 |
| `rebuild_sprites.py` | 一键重跑：raw 洋红底图 → 抠图 → 归一化，覆盖单姿态与序列帧 |
| `magenta_audit.py` | 洋红残留体检（抠图是否干净），入口带备份 |

**生成约定**（保证跨帧一致）：

1. 逐张生成、**不得并发**（输出文件名按时间戳，并发会互相覆盖丢帧），生成后立刻按 `姿态_序号` 重命名；
2. 新帧必须是 **image-to-image**（引用相邻帧为参考）+ `input_fidelity: high`，否则画风与比例会漂；
3. 背景固定 `flat solid pure magenta #FF00FF`，便于抠图；
4. 抠图判据用 `score = min(R,B) − G`，命中要求 `score > 30` 且 `B − G > 25` 且 `alpha > 50`；不用 R/B 比值（会误伤银灰毛发）。

**命名与排序坑**：`normalize_sequence.py` 按文件名排序，`sorted()` 会把 `_s10` 排在 `_s2` 前面——序列超过 9 帧必须改成数值感知排序。AI 原始文件名（如 `Walkframe{one,four,three,two}`）字典序是乱的，必须先重命名再入管线。

**预览**：`assets-src/previews/` 用于人眼验收——循环展开图（`walk_cycle.png` / `run_cycle.png`）、试听/对比页都在这里，由 `tools/sprites` 与 `tools/audio` 的 `make_*` 脚本**按需再生**（平时为空目录）。
