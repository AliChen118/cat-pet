# 06 · AI 自言自语

## 一、形态

**单向播报，没有对话。** 没有输入框、没有历史记录、不等回复、不追问——猫只是自己开口讲一小段：笑话、故事、诗、谜语（自问自答）、冷知识、随口说。

这条边界是刻意收窄的（早期版本设计过聊天窗与"说话条"，全部砍掉）：桌面宠物的价值是陪伴氛围，不是工具型对话；一旦引入输入通道，气泡节奏、让路规则、成本控制全部复杂化。

---

## 二、触发

| 触发 | 规则 |
|---|---|
| 自主（唯一自动入口） | 每 5s 判一次：**静置 ≥ 180s** + 未在讲 + 非 `sleep`/`drag` + 当前无其他气泡在播 → 按 `ai.autoTalk` 抽间隔后开口 |
| 手动 | 设置页「现在讲一段」（试听用，唯一手动入口；右键菜单不提供） |
| 频率 | `off` 不开 / `rare` 5–10 分钟 / `normal` 2–5 分钟 / `often` 1–2 分钟；**23:00–07:00 间隔翻倍** |
| 类别抽取 | 按权重轮盘（笑话 22 / 冷知识 22 / 随口说 22 / 故事 12 / 诗 11 / 谜语 11），命中上一段同类时顺延 |
| 阻塞 | 有交互立刻打断（`aiAbort`）；进入 `sleep` 时淡出停讲；拖动中不开口 |

---

## 三、内容规格

每类一条独立 system 指令 + 句数/字数/词元预算，硬截断不切半句：

| 类别 | 句数上限 | 字数上限 | tokens | 语音情境 | 要点 |
|---|---|---|---|---|---|
| 笑话 `joke` | 3 | 90 | 160 | `idle` | 猫咪视角冷幽默，末尾自嘲或反转 |
| 故事 `story` | 8 | 260 | 520 | `tired` | 小动物日常，有画面感，结尾轻落 |
| 诗 `poem` | 5 | 90 | 160 | `tired` | 短句具象；`|` 分行，气泡内保留换行 |
| 谜语 `riddle` | 3 | 80 | 150 | `idle` | 出题 + 自揭晓（无人互动，必须自答） |
| 冷知识 `fact` | 3 | 100 | 200 | `idle` | 真事实 + 一句猫咪吐槽 |
| 随口说 `idle` | 3 | 70 | 150 | `idle` | 结合时段/宠物状态/桌面情境 |

**全局硬约束**（写进 system）：只输出正文，不解释、不寒暄、不提"作为 AI"、不追问用户、不用 Markdown；温度 0.9（"猫味"比准确性重要）。

## 四、播放：句子队列

```
主进程生成整段 → 增量切句 → 逐句下发 ai-say {text, voiceKey, verse, last}
  → 渲染端入队（上限 8 句，超出丢尾部并在末句补「…」）
  → 逐条显示：hold = clamp(字数×118 + 780, 1500, 6000)ms × ai.bubblePace
  → 句间 350ms 空隙，换句弹跳，末句后淡出
```

- **生成与播放并行**：生成端 push、播放端按 hold 消费，首句零等待（不必等整段生成完）；
- **切句在主进程完成**，气泡与语音拿到同一节奏；
- **节奏倍率** `ai.bubblePace`：fast ×0.75 / normal ×1 / slow ×1.35。

**让路规则**（比"讲得流畅"更重要）：

| 情况 | 行为 |
|---|---|
| 抚摸 / 喂食 / 逗玩 / 呼喊 / 拖拽 | 立即 `clearQueue()` + `aiAbort()`，优先响应交互 |
| 属性危急提醒 | 插到队首，其余属性气泡在播报期间挂起 |
| 进入 `sleep` / `drag` | 淡出停讲 |

讲完自动停，**不连续追问、不等回复**。

### 4.1 打断必须「连气泡一起收」（1.2.0 修复）

`interruptAi()` 的语义是「这句话作废」。旧实现只做了 `clearTimeout(ai.showT)`——
定时器撤了、`.show` 没摘，气泡就永远停在屏幕上，直到下一次有别的台词把它顶掉。
用户侧看到的是：**气泡正在显示时拖一下猫，气泡长时间不消失，再点一下才消失**
（`pointerdown` 命中猫身就必然 `interruptAi()`，所以"拖拽"必然触发）。

现在的约束（`renderer.js`）：

| 入口 | 职责 |
|---|---|
| `hideBubble()` | **收气泡的唯一出口**：撤两条定时器 + 摘 `show` / `verse` + 清 `ai.text` |
| `showBubble()` | 普通台词：撤掉 `ai.showT`（否则 AI 的旧定时器会反手把新气泡提前收掉） |
| `aiShow()` | 记 `ai.text`，定时到点直接调 `hideBubble` |
| `interruptAi()` | 屏上仍是这句 AI 台词就 `hideBubble()`；已被别的话覆盖则只撤定时器 |
| `frame()` 看门狗 | `BUBBLE_MAX_LIFE = 20s` 兜底（AI 单句 hold 上限 8s），任何漏收路径都不会永久停留 |

`tools/check/test_logic.js` 有 5 条源级断言守着这组不变量，改回「只 clearTimeout」会直接红。

## 五、模型接入

**单协议：OpenAI 兼容** `POST {baseUrl}/chat/completions`，SSE 流式。

| 预设 | 地址 / 模型 | 免费情况 |
|---|---|---|
| `zhipu`（默认） | `https://open.bigmodel.cn/api/paas/v4` / `glm-4-flash` | 不限量免费，手机号注册 |
| `siliconflow` | `https://api.siliconflow.cn/v1` / `Qwen/Qwen3-8B` | 小模型永久免费（实名） |
| `modelscope` | `https://api-inference.modelscope.cn/v1` / `Qwen/Qwen3-8B` | 每天 2000 次 |
| `dashscope` | `https://dashscope.aliyuncs.com/compatible-mode/v1` / `qwen-flash` | 每模型 100 万 token（90 天） |
| `ark` | 火山方舟兼容地址 | 每模型 50 万 token + 每日额度 |
| `deepseek` / `moonshot` | 各自 `/v1` | 需充值 |
| `ollama` | `http://127.0.0.1:11434/v1` | 本地免费无限量，**免密钥** |
| `custom` | 自填 | — |

免费额度会随平台调整，以官网为准。选预设自动填地址与模型名，可手改。

**请求细节**：走 `net.fetch`（跟随系统代理），`stream:true` 手动解 SSE（半包安全）；首字节 12s、整体 60s 超时；`onText` 返回 `false` 即断流省 token。

**错误分类**（翻译成人话，只弹一次气泡，不打断使用）：401 钥匙不对 / 402 余额 / 429 问得太快 / 404 地址或模型名 / 400 参数 / 5xx 服务端 / 断网 / 超时 / 被打断。

## 六、降级策略

**核心原则：失败不打扰。** 用户没配 Key、断网、Key 失效，都不该看到报错弹窗。

| 场景 | 处理 |
|---|---|
| 未配置 Key / 本地 Ollama | 直接用离线语料（本地地址免密钥） |
| 模型请求失败且**尚未开口** | 静默改用内置离线语料，来源在设置页「连接测试」可查原因 |
| 已经开口但**中途断流** | 把已收到的句子说完收尾，不硬切 |
| **8 秒内没憋出第一句** | 直接降级离线（模型排队时不让气泡空等） |
| 交互打断 | `aiAbort` 立刻唤醒等待中的生成，零延迟 |

**离线语料**：`engine/ai-fallback.js` 内置 88 条，覆盖 6 类，永久可用、与模型同一套去重逻辑。

## 七、防重复

自言自语没有多轮上下文，唯一要记住的是"别讲重复的"：

- `<dataDir>/ai-recent.json` 保存最近 **20 条** `{category, title, hash, ts}`；
- 生成时把最近同类标题注入 system（"最近讲过：…，请换一个"）；
- 同 `hash` 内容 **3 天内不再出现**；
- 离线语料走同一套去重；
- 设置页提供「清空播报记录」。

## 八、密钥与成本

| 项 | 做法 |
|---|---|
| 存储 | `<dataDir>/ai-secret.bin`，Windows DPAPI（`safeStorage`）加密；**不写入 config.json** |
| 展示 | UI 只显掩码 `sk-****abcd`；输入框留空表示不修改，填入即覆盖 |
| 输入校验 | 只读写系统对话框选中的文件，不接受渲染进程传来的任意路径 |
| 成本保护 | 内置 `max_tokens` 按类别封顶（150–520）+ 句数/字数硬截断 + 60s 总超时 + 首句 8s 降级 |
| 用量统计 | `ai-usage.json` 仍记录调用次数（仅供展示，**1.0.0 起不再设每日上限**） |

## 九、设置项（`ai` 组，11 项）

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | switch | **false** | 总开关（默认关，不打扰） |
| `preset` | select | `zhipu` | 模型服务预设 |
| `baseUrl` / `model` | text | 智谱地址 / `glm-4-flash` | 选预设自动填，可改 |
| `apiKey` | password | 空 | 加密存 `ai-secret.bin` |
| `testConn` / `sayNow` | action | — | 连接测试 / 立刻讲一段 |
| `autoTalk` | select | `normal` | off / rare / normal / often |
| `speech` | select | `purr` | off / purr（每段首句一声轻喵）/ tts（系统朗读） |
| `speechRate` | range | 100（80–140%） | 仅 `speech=tts` 生效 |
| `bubblePace` | select | `normal` | 句子停留节奏 |

**1.0.0 已下线**：`ai.dailyLimit`（每日上限，改为不设上限）、`ai.affectPet`（讲完加心情）——两者都会让"自言自语"变成需要管理的负担，不如只保留频率与预算控制。

**语音联动**：`purr` 只给每段**首句**配一声轻喵（长段中间再加一声），受语音模块 1200ms 全局节流自然限流，绝不逐句连叫；`tts` 用系统 `speechSynthesis` 按句排队朗读，不可用时该选项自动禁用并提示去系统设置添加语音。
