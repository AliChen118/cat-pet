# 03 · 属性与行为

行为系统由三块拼成：**FSM 负责"能做什么"**（状态与转换）、**needs-profile 负责"想做什么"**（分档与权重）、**renderer 的仲裁负责"最后做什么"**（优先级 + 冷却）。

---

## 一、状态机

15 个状态（`engine/fsm.js` 驱动，状态定义在 `renderer.js`），每个状态有 `enter / update / exit` 三个钩子：

| 状态 | 类别 | 说明 | 可被危急需求打断 |
|---|---|---|---|
| `idle` | 自主 | 呼吸待机、决策起点 | ✅ |
| `walk` | 自主 | 横向移动（含边界转身） | ✅ |
| `run` | 自主 | 快速移动 | ❌（位移中，打断会突兀） |
| `jump` | 自主 | 物理抛物线 + 落地 | ❌ |
| `fall` | 过渡 | 拖拽松手后的下落（复用 jump 帧，`startAt:1`） | ❌ |
| `stretch` | 自主 | 伸懒腰（单次后定格） | ❌ |
| `sleep` | 自主 | 趴睡，冒 Zzz | **❌ 刻意排除** |
| `eat` | 交互 | 走向食碗 → 低头 → 咀嚼 → 结算 | ❌ |
| `play` | 交互 | 逗猫球动画 → 结算 | ❌ |
| `pet` | 交互 | 蹭头，冒爱心 | ❌ |
| `bath` | 交互 | 坐盆 + 泡泡 + 抖身 → 结算 | ❌ |
| `meow` | 自主/交互 | 喵叫，冒气泡 | ✅ |
| `tailwag` | 自主 | 摇尾巴 | ✅ |
| `unhappy` | 自主 | 蔫着不高兴 | ✅ |
| `drag` | 交互 | 被拎起（单帧） | ❌ |

**为什么 sleep 不可打断**：无人互动时以趴睡为主（默认 70%），若"饿了/累了"能打断睡眠，趴睡节奏会被彻底打碎。取而代之的是**醒来那一刻补检**并立刻反应。

**转换主干**：

```
idle ──决策──► walk ──加速──► run
  │             │  ◄──减速──┘
  │             └──(到边缘/随机)──► jump ──落地──► idle/walk
  ├──(困/趴睡倾向)──► sleep ──睡醒──► stretch ──► idle
  ├──(长时间无互动/需求)──► meow ──► idle（呼喊后走向光标）
  ├──(随机表)──► tailwag / unhappy / stretch
  └──(喂食)──► walk(走向碗) ──► eat ──► idle

任意状态 ──(拖拽)──► drag ──(松手)──► fall ──(落地)──► idle
任意状态 ──(抚摸/逗玩/洗澡)──► pet / play / bath ──► idle
```

所有交互入口统一包一层 `wakeIfSleeping(next)`：睡着时先唤醒（冒唤醒台词 + 唤醒喵叫）再进入目标状态，避免"睡着被直接拖进 play"。

## 二、属性模型

`runtime.stats` 六个字段，除 `xp` 外均夹紧到 `[0, 100]`：

| 字段 | 首次启动默认 | 含义 |
|---|---|---|
| `hunger` | 80 | 饱食（越低越饿） |
| `energy` | 80 | 体力 |
| `happiness` | 80 | 心情 |
| `cleanliness` | 80 | 清洁 |
| `affinity` | 10 | 好感（长期关系值） |
| `xp` | 0 | 经验，`等级 = floor(xp/100)+1`；等级仅内部保留，面板改为显示年龄 |

首次启动四项状态均为 80（全 good 档），不会一上来就抱怨。

## 三、衰减

**统一口径**：设置项是"每 30 分钟下降多少点"，运行时换算成匀速：

```
decayPerSec(stat) = decayX / 1800      // 单位：点/秒；decayX = 0 表示该属性不下降
```

默认 `decayHunger/Energy/Happiness/Cleanliness/Affinity = 20/20/5/20/3`（心情与好感天然更耐久）。

| 情境 | 倍率 |
|---|---|
| 趴睡 | 饱食 ×1/3、清洁 ×0.25、心情 **+0.05/s**（缓慢回升）、好感不掉 |
| 奔跑 / 玩耍 | 清洁 ×2.2 |
| 睡觉 | 体力 **+9/s**（不受 `decayEnergy` 影响） |

> 衰减各项**互相独立**，设置成 0 即"该项养成暂停"，不影响其他属性与行为逻辑（档位恒定，跨档检测自然不触发）。

## 四、交互结算

| 交互 | 入口 | 即时收益 | 动作中持续 | 结算（动作结束） |
|---|---|---|---|---|
| 抚摸 `pet` | 左键点猫 / 菜单 / 面板 | 心情 +8、xp +3、好感 +3 | 心情 +7/s | — |
| 喂食 `feed` | 菜单 / 面板 | xp +4、好感 +2 | — | 饱食 +42、心情 +6 |
| 逗玩 `play` | 菜单 / 面板 | xp +5、好感 +3 | — | 心情 +26、体力 −14 |
| 呼喊 `call` | 菜单 / 面板 / 托盘双击 / 热键 | 心情 +8、xp +2、好感 +1 | — | 走向光标 |
| 洗澡 `bath` | 菜单 / 托盘 / 面板 | — | — | 清洁 +55、心情 +10、体力 −6、好感 +2、xp +6 |

结算后立即 `flushStats()` 把属性推给主进程持久化，并冒专属台词；该台词有 **1.2s 保护窗口**不被属性气泡覆盖。

## 五、分档与灵敏度

`engine/needs-profile.js` 是**唯一来源**：阈值、权重乘子、优先级都在这里，`renderer.js` 只消费。

每项 0–100 分四档：`critical`（危）/ `low`（偏低）/ `normal`（正常）/ `good`（良好）。

| 属性 | 危 `critical` | 偏低 `low` | 良好 `good` |
|---|---|---|---|
| 饱食 | `< 15` | `15–34` | `≥ 70` |
| 体力 | `< 15` | `15–34` | `≥ 70` |
| 心情 | `< 20` | `20–44` | `≥ 70` |
| 清洁 | `< 15` | `15–39` | `≥ 70` |

**灵敏度**（`behavior.needSensitivity`）整体平移 T1/T2，不动良好档（避免压缩正反馈）：宽松 −8 / 标准 0 / 严格 +8；T1 平移后下限夹到 `≥ 5`，保证危急区间永远非空。

**迟滞**：降档用原阈值，升档需越过 `阈值 + 4`（34.9 仍算偏低，39 才回正常）。迟滞只作用于气泡与档位快照；**行为权重用瞬时值**，不迟滞。

## 六、权重与乘子

基础表 `ACTIVITY` 按活跃度给出决策间隔与行为概率：

| 活跃度 | 决策间隔 | walk | idle | run | jump | stretch | meow | tailwag |
|---|---|---|---|---|---|---|---|---|
| `low` 安静 | 4.5–9.0s | 0.28 | 0.39 | 0.07 | 0.06 | 0.07 | 0.05 | 0.08 |
| `normal` 标准 | 2.2–5.5s | 0.36 | 0.16 | 0.16 | 0.08 | 0.08 | 0.06 | 0.10 |
| `high` 活泼 | 1.2–3.2s | 0.34 | 0.05 | 0.24 | 0.12 | 0.07 | 0.08 | 0.10 |

每项属性的档位对应一行乘子，合成规则：

1. 取四项属性各自档位的乘子行；
2. **逐列相乘**（任一列出现 0 即硬否决该行为）；
3. 每个乘子 `clamp 到 [0.05, 3.5]`（防极端归零/爆表）；
4. 与基础权重相乘后**归一化到总和 1**；
5. 结果再走仲裁。

**语义**：又困又饿 → 不跑不跳、多发呆多伸懒腰多喵叫；心情好 + 干净 → 跑跳与摇尾巴明显增多；脏到极危 → **完全不摇尾巴**（掩饰不适）。

**趴睡倾向**（`behavior.restiness`，默认 70）：

```
restiness_eff = clamp( base + 活跃度偏移(低 +15 / 高 −20)
                            + 体力低 +25 / 体力好 −10
                            + 心情危 +10 / 心情好 −5
                            + 清洁危 +8 / 饿极 −15 , 0, 100) / 100
```

（"饿极 −15"是刻意的：饿得睡不着。）

## 七、仲裁：一次只出一个行为 + 一句气泡

`decide()` 按 P1→P10 自上而下判定，**命中即返回**：

| 优先级 | 条件 | 行为 | 气泡 |
|---|---|---|---|
| P1 | 体力危 | 强制 `sleep` | 疲惫类台词 |
| P2 | 饱食危 | 强制 `meow`（讨食） | 饿类台词 |
| P3 | 清洁危 | 50% `unhappy` / 50% `meow` | 脏类台词 |
| P4 | 心情危 | 50% `unhappy` / 50% `meow` | 难过类台词 |
| P5 | 心情偏低 | 40% `unhappy`，否则继续往下判 | 闹别扭类台词 |
| P6 | 其余偏低档 | 不强制，仅走加权表 | 概率性出对应提醒 |
| P7 | 超时无互动 > `callInterval` | `meow` | 孤独类台词 |
| P8 | 四项全良好且冷却已过 | — | 6% 概率正向台词 |
| P9 | — | 按 `restiness_eff` 决定是否 `sleep` | — |
| P9.5 | 距上次舔爪 > 90 s，且 `rand < 0.05 × cleanFactor` | `lick`（1–2 轮随机） | — |
| P10 | — | 加权随机表（含乘子） | — |

**P9.5 空闲舔爪**：独立冷却 + 低概率，**不进加权表**（`needs-profile.js` 的 `ACTIONS` 不含 `lick`）——若进表会挤占 `walk`/`idle`/`run` 的比例，且间隔不可控。`cleanFactor()` 在 `cleanliness` 非 good 档时返回 2（脏了更爱舔），否则 1。决策间隔 2.2–5.5 s，叠 90 s 冷却后实际约 **90–130 s 出现一次**。进食结束属于**必定触发**，不走这条分支，见 `eat.update` 末段。

**舔爪的结束时刻挂在动画时钟上**（`pet.lickEnd = animator.clock + rounds × 0.95 - 0.1`），不是墙钟。原因：帧推进走的是 `dt × animSpeed()`，而默认动效速度是 85%，2 轮实际要 1.9/0.85 ≈ 2.24 s；若用墙钟累加 1.9 s 就切换状态，收爪帧根本没机会播完。末尾的 `- 0.1`（半帧）用于避开环回：状态切换发生在 `animator.update` 之前，不提前退出就会在淡出期闪回 `lick_1` 的抬爪姿态。

**多个危急同时出现**：按 P1→P4 顺序只执行最高优先级项，被压下的需求**不丢弃**，下一轮继续参评，天然形成轮转，不会"永远只喊饿"。

## 八、实时性：三个触发通道

| 通道 | 时机 | 作用 |
|---|---|---|
| ① 帧级跨档检测 | 每帧，属性衰减后 | 穿越阈值瞬间出对应台词（降档给警示、升档给恢复语），20s/属性 冷却 |
| ② 紧急中断 | 每帧 `maybeUrgent()` | 危急需求不等决策 tick，在可打断状态立刻切换（8s/需求 冷却） |
| ③ 交互结算 | 喂食/洗澡/逗玩/抚摸结束 | 属性跳变由 ① 捕获 → 出"吃饱饱，好幸福～"这类正向台词 |

**可打断集合**只有 `{idle, walk, meow, tailwag, unhappy}`；`sleep` 与全部交互/物理动作都不可打断。

## 九、冷却与限流

| 通道 | 冷却 | 目的 |
|---|---|---|
| 自主气泡（全局） | 5s | 防刷屏 |
| 同一属性常规提醒 | 90s | 同一件事不连续唠叨 |
| 危急档提醒 | 45s | 比常规更勤，避免饿/累被憋住 |
| 跨档即时反应 | 20s / 属性 | 即时反馈值得宽松一点 |
| 正向（good 档）气泡 | 200s + 6% 概率 | 必须稀罕才有惊喜感 |
| 紧急中断 | 8s / 需求 | 防来回横跳 |
| 交互结算台词保护 | 1.2s | 结算语不被状态气泡覆盖 |

**总开关** `behavior.needVoice`：关闭后属性不再影响台词与动作倾向（清洁完全退出），仅保留体力/饱食的危急保护——用于对照排查"是不是属性在作怪"。

## 十、边界规则

| 场景 | 处理 |
|---|---|
| 睡眠中属性跌到危急 | 不出气泡、不中断；醒来立即补检 |
| 拖拽中 | 不在可打断集合，一切状态驱动暂停 |
| 交互动作进行中 | 不强制切换；气泡受 1.2s 保护 |
| `needVoice=false` | 只保留体力/饱食危急保护，行为回到纯基础表 |
| 清洁类台词 | 1.0.0 起洗澡入口恒开放，「允许洗澡」设置已下线，台词始终可用完整句式 |
| 属性为 0 | 恒判 `critical`，不出现 `NaN` |
| 属性恰在阈值抖动 | 迟滞 +4 解决 |
| 状态面板未打开 | 属性照常驱动（面板只是显示层） |
